# Ad Light — ТЗ на обновление геймплея (v0.2)

## Как пользоваться документом

Каждая задача самодостаточна: агенту достаточно прочитать раздел «Контекст проекта» и саму задачу.
Задачи выполняются по одной, строго в порядке номеров (зависимости описаны в графе ниже).
После каждой задачи — `bun run typecheck`, `bun run build` и ручной прогон затронутого уровня.
Одна задача = один коммит.

## 0. Контекст проекта

### Стек и команды

- Phaser 3.88 (Arcade Physics, Light2D), TypeScript, Vite, Bun.
- `bun run dev` — разработка, `bun run build` — сборка, `bun run typecheck` — проверка типов.
- Из rexUI импортируется **только** `phaser3-rex-plugins/templates/ui/label/Label` (плагин целиком не подключён, не возвращать его).

### Структура

```
src/
  config.ts                 единственный источник чисел (баланс, тайминги, описание уровней)
  index.ts                  регистрация сцен, уровни подхватываются глобом ./scenes/levels/*.ts
  scenes/
    BaseScene.ts            фейды, centerX/centerY, onSceneEvent, onResize, fullscreenToggle
    BootScene.ts PreloadScene.ts StartScene.ts PauseScene.ts
    GameOverScene.ts WinScene.ts EndScene.ts
    GameScene.ts            общий каркас игрового уровня
    levels/Level1Scene.ts   super('Level1Scene', config.levels[1]) — и всё
  game/
    GameManager.ts          состояние игры, спавн, коллизии, счёт
    LevelManager.ts         параллакс-слои, планктон
    Player.ts MovementController.ts BubbleEmitter.ts Mollusk.ts textures.ts
    Enemy.ts                текущий удильщик (внутри TODO про базовый класс)
    enemies/Kraken.ts       босс 3 уровня
    enemies/AnglerFish.ts   пустая заготовка
    enemies/SwallowtailFish.ts пустая заготовка
  ui/Gui.ts                 кнопки и фоновые картинки меню
```

### Существующие сущности, на которые опираются задачи

- `BaseScene.onSceneEvent(event, handler)` и `BaseScene.onResize(handler)` — подписки, которые
  автоматически снимаются на `SHUTDOWN`. Все новые подписки только через них.
- `BaseScene.fadeToScene(target, params, callback)` — защищён от двойного вызова.
- `GameScene` — конструктор `(key: string, levelConfig: LevelConfig)`, хуки: `createLevel()` (protected,
  переопределяется уровнями), `update(time, delta)`, `handleResize()`, `createPlayerUI()`, `updateUI()`.
- `GameManager` — `startGame(config)`, `update()`, `setupCollisions(player)`, `isPlaying()`, `winGame()`,
  `loseGame()`, `addScore()`, `getScore()`. Внутри: `enemiesGroup`, `mollusksGroup`, `mouthsGroup`,
  `enemyByObject` и `molluskBySprite` (WeakMap), массивы `enemies` и `mollusks`.
- `Player` — `update(time, delta)`, `takeDamage(amount)`, `die()`, `isAlive()`, `getHealth()`,
  `setInvulnerable()`, `canInvulnerable()`, `isMoving(threshold)`, приватные `updateLight(delta)`,
  `createMoveWave()`, `becomeInvulnerable()`.
- `MovementController` — `getInputDirection()` возвращает нормализованный вектор, `isInputActive()`,
  `isMoving(threshold)`, `disable()`.
- `Enemy` — `update(playerX, playerY, isPlayerAlive)`, `getSprite()`, `getMouthCollider()`,
  `bounceOffBounds(body)`, `onPlayerHit()`, состояния `Idle`/`Chase`.
- `LevelManager` — слои описаны структурой `LevelLayer { sprite, parallax, cover, textureHeight }`,
  есть `createLevel({ textures, plankton })`, `update()`, `resize()`.
- `textures.ts` → `ensureTexture(scene, key, width, height, draw)` — генерация текстуры один раз на игру.

### Технические ограничения (нарушение = баг)

1. **Игра идёт в 30 FPS** (`fps.target: 30`, `forceSetTimeOut: true`, arcade `fixedStep`). Любое движение и
   любая анимация считаются от `delta`. Паттерн уже есть: `REFERENCE_FRAME_MS = 1000 / 30` в `Player.ts`
   и `Kraken.ts`. Ни одного расчёта «на кадр» без `delta`.
2. **Никаких `setInterval` / `setTimeout`** — только `scene.time.addEvent` и `scene.time.delayedCall`,
   иначе таймер переживёт сцену (такой баг уже был на 3 уровне).
3. **Light2D ограничен количеством источников** (`render.maxLights`, по умолчанию 10). Уже сейчас на
   2 уровне 12 удильщиков + 15 моллюсков + игрок = 28 источников, часть не рендерится. Прежде чем
   добавлять свет медузам, поднять `render.maxLights` (16–20) и **замерить FPS**; если просадка —
   у дальних моллюсков заменить реальный свет на glow-спрайт.
4. **Режим масштабирования `Phaser.Scale.RESIZE`** — размер вьюпорта меняется в любой момент. Каждый
   новый визуальный элемент обязан корректно переживать ресайз (через `handleResize` / `layout`).
5. **Звуки только через `scene.sound.play(key, config)`**. `sound.add(...).play()` оставляет экземпляры
   в `SoundManager` и течёт.
6. **Генерируемые текстуры только через `ensureTexture`** — ключи текстур глобальны для игры.

### Правила кода (обязательны для каждой задачи)

- Все числа, тайминги и вероятности — в `config.ts`. В классах магических чисел нет.
- Никаких лишних комментариев: комментарий только там, где код не объясняет сам себя
  (неочевидное ограничение движка, причина порядка вызовов).
- Без обратной совместимости и без fallback-логики, если это не оговорено в задаче.
- Дублирование кода не плодить: общее поведение врагов — в базовый класс, общая логика уровней —
  в `GameScene`, UI — в `src/ui/`.
- Новые системы кладутся в `src/game/systems/`, новые враги — в `src/game/enemies/`.
- Типизация строгая, `any` только там, где типы Phaser этого требуют.

### Definition of Done для любой задачи

- `bun run typecheck` и `bun run build` без ошибок.
- Прогон: меню → уровень → пауза (ESC) → возврат → смерть → «Again» (рестарт уровня) → выход в меню.
  В консоли браузера нет ошибок и предупреждений.
- Ресайз окна во время игры не ломает геометрию и не оставляет мусор.
- Количество звуков, твинов и таймеров не растёт при повторном заходе на уровень.
- Существующие фичи целы: кракен на 3 уровне, пауза, фейды, титры, рекорды (после задачи 12).

## Задача 1. Базовый класс врагов

**Зачем.** Сейчас `Enemy.ts` — единственный тип врага, а `enemies/AnglerFish.ts` и
`enemies/SwallowtailFish.ts` — пустые заготовки с комментарием `// extend Enemy`. Без общей базы три
новых врага превратятся в три копии одного кода.

**Файлы.** Создать `src/game/enemies/BaseEnemy.ts`. Перенести текущую логику в
`src/game/enemies/AnglerFish.ts`. Удалить `src/game/Enemy.ts` и `src/game/enemies/SwallowtailFish.ts`
(заготовка будет создана заново в задаче 6). Правки: `GameManager.ts`, `config.ts`.

**Что сделать.**

1. `BaseEnemy` — абстрактный класс с общим для всех врагов:
   - спрайт с физическим телом, `setPipeline('Light2D')`, `body.onWorldBounds = true`;
   - опциональный источник света с оффсетом, обновляемый по `flipX`;
   - опциональный коллайдер-«пасть» (`getHitArea()`), у медузы это само тело;
   - `update(delta, context)`, где `context` — `{ playerX, playerY, isPlayerAlive, noise, playerLightRadius }`;
   - `bounceOffBounds(body)`, `keepInsideBounds()`, `getSprite()`, `destroy()`;
   - шаблонный метод `protected abstract think(delta, context)` — вся уникальная логика в наследниках;
   - `destroy()` обязан снимать свет через `scene.lights.removeLight` и убивать свои таймеры.
2. `AnglerFish` — текущее поведение `Enemy` без изменений баланса (переезд один-в-один). Поведение
   меняется в задаче 5, здесь только рефакторинг.
3. Спавн по типам. В `config.ts` заменить `EnemiesConfig { count: number }` на:

```ts
export type EnemyKind = 'anglerFish' | 'swallowtail' | 'jellyfish';

export interface EnemySpawnConfig {
  kind: EnemyKind,
  count: number,
  indent?: { top?: number, bottom?: number, left?: number, right?: number },
}
```

   В `LevelConfig` поле `enemies: EnemySpawnConfig[]`. Текущие уровни: 1 → `[{ kind: 'anglerFish', count: 8 }]`,
   2 → `[{ kind: 'anglerFish', count: 12 }]`, 3 → `[]`.
4. В `GameManager.spawnEnemies` — фабрика по `kind` (простая мапа `kind → конструктор`), минимальная
   дистанция до игрока и попытки спавна остаются (`SPAWN_MIN_DISTANCE_TO_PLAYER`, `SPAWN_MAX_TRIES`).
   Регистрация в `enemyByObject` и добавление в `enemiesGroup` / `mouthsGroup` — как сейчас.

**Критерии приёмки.** Уровни 1 и 2 играются ровно как до задачи: враги дрейфуют, гонятся с 300 px,
бьются в границы мира, кусают игрока. Диффа в поведении нет.

**Не делать.** Не менять баланс, не трогать кракена (он остаётся отдельным классом), не добавлять
новых врагов в этой задаче.

## Задача 2. HUD в отдельный класс

**Зачем.** Дальше в HUD добавляются полоска света, таймер и подсказки обучения. Сейчас HUD живёт прямо
в `GameScene` (`createPlayerUI`, `updateUI`, `scoreText`, `hearts`), сцена начнёт раздуваться.

**Файлы.** Создать `src/ui/Hud.ts`. Правки: `GameScene.ts`.

**Что сделать.**

1. Класс `Hud(scene)` с методами `create()`, `setMollusks(collected, total)`, `setHealth(value, max)`,
   `layout()`, `destroy()`. Внутри — кэширование прошлых значений, чтобы `setText` не вызывался каждый

**Критерии приёмки.** HUD выглядит и ведёт себя как раньше, `GameScene` стал короче, при ресайзе HUD
остаётся в углу.

## Задача 3. Свет как ресурс

**Зачем.** Ядро игры называется «Ad Light», но свет ничего не делает: он всегда включён и его радиус
(450) больше радиуса обнаружения врага (300), поэтому угрозы нет. Свет должен стать расходником,
который восполняют моллюски — тогда сбор превращается из счётчика в выживание.

**Файлы.** Создать `src/game/systems/LightFuel.ts`. Правки: `Player.ts`, `GameManager.ts`,
`src/ui/Hud.ts`, `config.ts`, `GameScene.ts`, `MovementController.ts` (клавиша притухания).

**Что сделать.**

1. `LightFuel` держит запас `fuel` в диапазоне 0…`fuelMax` и умеет:
   - `update(delta, { dimmed, drainMultiplier })` — расход `drainPerSecond` (умножается на
     `dimDrainMultiplier`, если свет притушен, и на `drainMultiplier` из уровня, см. задачу 12);
   - `refill(amount)` — восполнение при сборе моллюска;
   - `getRatio()` → 0…1, `isEmpty()`;
   - `getRadius()` — линейная интерполяция `radiusMin`…`radiusMax` по `getRatio()`;
   - события `light-empty` и `light-restored` (через `scene.events.emit`), чтобы HUD и звук
     реагировали без опроса каждый кадр.
2. `Player.updateLight(delta)` берёт радиус и интенсивность из `LightFuel`: радиус — `getRadius()`,
   интенсивность — интерполяция `intensityMin`…`intensityMax` по `getRatio()`. Существующая пульсация
   (`pulseTime`, `sin`) сохраняется, но её амплитуда тоже масштабируется от запаса: на исходе света
   свет должен нервно мигать.
3. Притухание света: удержание **SHIFT** (добавить клавишу в `MovementController.keys` или отдельным
   `addKey`, не ломая раскладку WASD/стрелок). Пока клавиша зажата: радиус едет к `dimRadius` за
   `dimTransitionMs`, расход падает до `dimDrainMultiplier`, флаг `isDimmed()` доступен снаружи (нужен
   задаче 4 для заметности). Отпустил — возврат к текущему радиусу за то же время.
4. Восполнение: в `GameManager.collectMollusk` вызвать `refill(fuelPerMollusk)`. Существующие
   `addScore(1)` и звук `drip` остаются.
5. Давление темноты: пока `isEmpty()`, копится таймер; каждые `darknessGraceMs` игрок теряет
   1 здоровье (`player.takeDamage(1)`). Таймер сбрасывается при первом же восполнении.
   Реализация — `scene.time.addEvent`, который создаётся на `light-empty` и убивается на
   `light-restored`, а не постоянный опрос.
6. HUD: вертикальная или горизонтальная полоска света (два прямоугольника — рамка и заполнение,
   без новых ассетов) рядом с сердцами. Цвет заполнения интерполируется `0xcff1ff` → `0xff6a4a`
   по `getRatio()`. Ниже `lowFuelThreshold` — мягкое мигание полоски (твин, не пересоздавать каждый кадр).
7. Звук: на `light-empty` — `depth` (уже загружен) один раз, тихо.

**Числа.** См. приложение A, блок «Свет».

**Критерии приёмки.** С полным светом радиус 500, за ~70 секунд без сбора он падает до 120, четыре
моллюска возвращают полный запас. SHIFT ощутимо гасит свет и экономит запас. При нулевом запасе игрок
теряет сердце каждые 15 секунд, но не мгновенно. Полоска в HUD соответствует состоянию, при рестарте
уровня запас сбрасывается в `fuelStart`.

**Не делать.** Не делать смерть от темноты мгновенной. Не убирать пульсацию света. Не менять
`maxHealth`.

## Задача 4. Волны как шум: обнаружение по звуку и свету

**Зачем.** У игрока уже есть механика, которая идеально подходит на роль сигнала обнаружения, но никуда
не подключена: ряби-волны, которые `Player.createMoveWave()` спавнит каждые 300 мс во время движения.
Если враги будут реагировать на шум и на свет, а не на позицию игрока напрямую, скорость станет
осознанным решением: рванул через открытое место — услышали, крадёшься с притушенным светом — прошёл.

**Файлы.** Создать `src/game/systems/NoiseField.ts`. Правки: `Player.ts`, `GameManager.ts`,
`enemies/BaseEnemy.ts`, `config.ts`.

**Что сделать.**

1. `NoiseField` — маленький пул активных «пингов»: `{ x, y, radius, bornAt }`.
   - `emit(x, y, speed)` — радиус интерполируется `noiseRadiusMin`…`noiseRadiusMax` по текущей скорости
     игрока (от порога движения до `player.speed`);
   - `update(now)` — снимает пинги старше `noiseLifetimeMs`;
   - `getLoudnessAt(x, y)` → 0…1 — максимальная громкость в точке с линейным затуханием от центра
     пинга к его радиусу;
   - пул фиксированного размера (`maxPings` 8, переиспользование объектов, без аллокаций в кадре).
2. `Player.createMoveWave()` дополнительно вызывает `noiseField.emit(...)`. Визуал волны не меняется.
   Дополнительно: при получении урона и при рывке — разовый громкий пинг (`noiseRadiusMax`).
3. `GameManager` владеет `NoiseField`, обновляет его в `update()` и передаёт врагам в контексте:
   `{ playerX, playerY, isPlayerAlive, noise: noiseField, playerLightRadius, playerDimmed }`.
4. `BaseEnemy` получает защищённый метод `protected sensePlayer(context): number` → 0…1, единая формула
   заметности для всех врагов:
   - слух: `context.noise.getLoudnessAt(this.x, this.y)`, умноженный на `hearingFactor` типа врага
     и обрезанный радиусом `hearRadius`;
   - зрение: игрок виден, если `distance < playerLightRadius * lightDetectionFactor`, вес `sightFactor`;
   - итог — максимум из двух каналов; выше `alertThreshold` враг переходит в тревогу.
     Слепые враги задают `sightFactor: 0`, глухие — `hearingFactor: 0`.
5. `AnglerFish` временно продолжает использовать текущую логику дистанции, но переключается на
   `sensePlayer()` в задаче 5. Чтобы не оставлять уровень сломанным, в этой задаче: если
   `sensePlayer() > alertThreshold` — гнаться, иначе прежний `distanceVision`-фолбэк убрать
   и оставить только новую формулу (проверить, что уровень 1 проходится).

**Числа.** Приложение A, блок «Шум и заметность».

**Критерии приёмки.** Стоя на месте с притушенным светом, игрок не привлекает врага с 250 px.
На полной скорости враг реагирует с ~400 px. Формула работает и на клавиатуре, и на управлении
мышью/тачем (там скорость тоже полная). Профилировать: `NoiseField` не создаёт объектов в `update`.

**Не делать.** Не превращать это в полноценный стелс с индикатором обнаружения — только реакция врагов.

## Задача 5. Удильщик-засада

**Зачем.** У удильщика есть светящаяся приманка (`lightRadius` 46, жёлтый свет) — то есть визуально это
рыба-ловушка, а ведёт себя как обычный преследователь, которого игрок легко обгоняет (100 против 260).
Нужно, чтобы его свет стал приманкой, а не декором: игрок должен учиться не доверять источникам света.

**Файлы.** `src/game/enemies/AnglerFish.ts`, `config.ts`.

**Что сделать.**

Конечный автомат вместо `Idle`/`Chase`:

1. **Lure** (по умолчанию). Стоит у своей точки спавна, микро-дрейф в радиусе `postDriftRadius`,
   свет ритмично пульсирует (`lureIntervalMs`, интенсивность `lureIntensityMin`…`lureIntensityMax`).
   Ждёт `sensePlayer() > alertThreshold`.
2. **Alert.** Разворачивается к игроку, свет резко ярче, замирает на `telegraphMs` — окно, в которое
   игрок может отреагировать. Если игрок вышел за `lungeRange` — назад в Lure.
3. **Lunge.** Рывок в сторону игрока со скоростью `lungeSpeed` в течение `lungeDurationMs`.
   Урон наносится только в этом состоянии (пасть активна), кадр атаки — существующий `setFrame(3)`.
4. **Recover.** `lungeCooldownMs` без атак, свет тусклый, возврат к точке спавна со `returnSpeed`.
   Затем Lure.

Дополнительно: пасть (`mouthCollider`) включается/выключается через `body.enable`, чтобы вне рывка
удильщик был безопасен — это делает его читаемым.

**Числа.** Приложение A, блок «Удильщик».

## Задача 11. Вертикальный режим уровня

**Зачем.** Тема Ludum Dare была «Depths», а все уровни — горизонтальные коридоры высотой в один экран.

Тестовый вертикальный уровень: камера едет вниз, параллакс работает по вертикали, стены не

## Задача 13. Таймер уровня и рекорды

**Зачем.** Игра проходится один раз и заканчивается. Время прохождения и отметка «без урона» дают
повод вернуться, при минимальных затратах.

**Файлы.** Создать `src/game/ProgressStore.ts`. Правки: `GameScene.ts`, `src/ui/Hud.ts`,
`WinScene.ts`, `GameOverScene.ts`, `config.ts`.

**Что сделать.**

1. `ProgressStore` — обёртка над `localStorage`:
   - ключ `ad-light:progress:v1`, схема
     `{ version: 1, levels: { [sceneKey]: { bestTimeMs: number, noDamage: boolean } }, totalBestMs?: number }`;
   - чтение через `try/catch` (приватный режим и переполнение квоты) и **валидация формы данных**
     перед использованием: неизвестная версия или некорректный тип — молча начинать с чистого
     прогресса, не падать и не доверять содержимому хранилища;
   - запись тоже в `try/catch`, ошибка записи не должна ломать переход между сценами.
2. Таймер уровня: старт в `GameManager.startGame`, стоп в `winGame()`. Считать по игровому времени
   (`scene.time.now` дельтами), чтобы пауза не накручивала время. Формат `m:ss.d`.
3. HUD: время в правом верхнем углу, обновление раз в `timerUpdateMs` (100 мс), а не каждый кадр.
4. По завершении уровня — короткий тост на `resultToastMs` перед фейдом: время, лучшее время,
   отметка «без урона», подсветка нового рекорда. В `WinScene` — суммарное время прохождения и
   лучший результат.
5. Флаг «без урона» — сбрасывается в `Player.takeDamage`, включая урон от темноты и от медуз.

**Числа.** Приложение A, блок «Рекорды».

**Критерии приёмки.** Время не растёт на паузе. Рекорд сохраняется между перезагрузками страницы,
повреждённые данные в `localStorage` не приводят к падению игры. Тост не задерживает переход
дольше `resultToastMs` и не появляется при смерти.

**Не делать.** Не делать онлайн-лидерборд, не собирать никаких данных об игроке.

## Приложение C. Риски

1. **Лимит источников света.** Самый вероятный источник просадки FPS. Медузы и приманки удильщиков
   добавляют свет туда, где его и так больше `maxLights`. Замерять после задач 5 и 7.
2. **Зум камеры и Light2D.** Проверить совпадение источников света со спрайтами при `zoom != 1`
   (задача 9). Если рассинхрон — уменьшить эффект.
3. **30 FPS и `forceSetTimeOut`.** Кракен и часть эффектов настроены под этот режим. Не менять
   `fps.target` в рамках этих задач: балансировка врагов и рывков привязана к нему.
4. **Вертикальный режим** трогает общий каркас `GameScene` и `LevelManager` — после задачи 11
   обязателен регресс-прогон всех уровней 1–3, а не только нового.
5. **Пауза.** Любая новая механика на таймерах и накопленном `delta` должна замирать на паузе.
   Проверять каждую задачу через ESC.
6. **Сложность.** Свет-ресурс + новые враги + давление темноты вместе могут сделать игру заметно
   злее. После задачи 7 сделать плейтест и при необходимости ослабить `drainPerSecond` и число врагов,
   а не убирать механики.
